Лабораторная работа № 3. Киберучения на полигоне Ampire
Тема: устранение уязвимости PyLoad (CVE-2023-0297)
Цель работы
Получить практические навыки обнаружения и устранения уязвимостей в информационной системе, анализа сетевых соединений и проверки последствий компьютерной атаки на учебном полигоне Ampire.
Исходные данные
В лабораторной работе исследовался сервер с установленным менеджером загрузок PyLoad:
- адрес узла: 10.10.2.29;
- веб-интерфейс: http://10.10.2.29:9666;
- доступ к серверу: SSH;
- уязвимость: CVE-2023-0297;
- адрес узла нарушителя в сценарии: 10.10.4.55.
CVE-2023-0297 позволяет выполнять Python-код на уязвимом сервере через обработку запросов с использованием библиотеки js2py. Согласно методическим материалам, проблема затрагивает версии PyLoad до 0.5.0b3.dev30 включительно.

Задача заключалась в исправлении уязвимого кода, поиске признаков закрепления нарушителя в системе и прекращении обнаруженного вредоносного соединения.
Ход работы
1. Подключение к серверу
К узлу PyLoad было выполнено подключение по SSH. Для дальнейшей работы использовалась оболочка с правами root.
ssh user@10.10.2.29
sudo -i

2. Исправление уязвимости CVE-2023-0297
Для устранения уязвимости был выбран способ изменения исходного кода, приведённый в методических материалах. В редакторе nano был открыт файл:
nano /usr/local/lib/python3.9/dist-packages/pyload/core/utils/misc.py
До исправления в начале файла присутствовали обычные импорты socket, js2py и is_mapping.

В файл были внесены следующие изменения:
- закомментирована строка import socket;
- закомментирована строка from .check import is_mapping;
- после import js2py добавлен вызов js2py.disable_pyimport().
В результате начало файла приобрело следующий вид:
import random
#import socket
import string

import js2py

#from .check import is_mapping
js2py.disable_pyimport()

Добавленный вызов отключает механизм pyimport библиотеки js2py, через который в рассматриваемом сценарии возможно небезопасное выполнение кода. На скриншоте зафиксировано внесённое исправление. Отдельного подтверждения перезапуска службы PyLoad в материалах нет.
3. Обнаружение вредоносного соединения
Далее были просмотрены активные TCP-соединения сервера командой:
ss -tp4
В списке обнаружено установленное соединение с узлом нарушителя 10.10.4.55:7897. Его обслуживал процесс evil.conf с идентификатором PID 640.

Наличие соединения указывало на то, что в системе продолжал работать посторонний процесс, связанный с последствиями атаки.
4. Поиск файла и механизма автоматического запуска
Чтобы найти исполняемый файл, использовалась команда:
find / -iname evil.conf
Поиск показал расположение файла:
/root/evil.conf

Затем была проверена таблица запланированных задач пользователя root:
crontab -l
В ней обнаружена запись:
*/1 * * * * /root/evil.conf

Такая запись запускает /root/evil.conf каждую минуту. Следовательно, простое завершение процесса не гарантирует окончательного устранения бэкдора: задача может создать новый процесс при следующем запуске.
5. Завершение вредоносного процесса
Для прекращения обнаруженной сессии была выполнена команда:
kill 640

После этого список соединений был проверен повторно:
ss -tp4
На повторном скриншоте соединение с 10.10.4.55:7897 отсутствует.

Таким образом, активная сессия, связанная с evil.conf, была прекращена.

Вывод
В ходе лабораторной работы был изучен сценарий эксплуатации CVE-2023-0297 в PyLoad. Удалось внести изменения в исходный код misc.py, обнаружить подозрительное сетевое соединение, определить путь к файлу evil.conf и найти задачу, запускающую его каждую минуту. После завершения процесса с PID 640 связь с узлом нарушителя на повторном снимке отсутствовала.
